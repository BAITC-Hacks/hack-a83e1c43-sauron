# Sauron: фронтенд и передача бэкендеру

Рабочий фронтенд взят из ветки `nurda`, коммит `39839a9`, и находится в корне проекта: `index.html` и `src/`. Неиспользуемый статический лендинг `Sauron/` удалён; при необходимости он доступен в истории Git. Локальный вариант `frontend/` удалён из проекта с резервной копией вне репозитория.

Для показа через один сервер выполните `npm ci`, `npm run build`, `python manage.py migrate`, `python manage.py seed_demo` и `python manage.py runserver`. Готовый сайт: **http://127.0.0.1:8000/**. Django отдаёт `dist/index.html`, ресурсы сборки доступны под `/static/ui/`, API — под `/api/v1/`. После изменения `src/` для этого режима нужна повторная сборка.

## Быстрый запуск на этом компьютере

Дважды нажмите `start-sauron.cmd` или выполните из корня:

```powershell
npm start
```

Сайт разработки: http://127.0.0.1:5173. Django: http://127.0.0.1:8000. Скрипт открывает браузер, повторно использует уже запущенные серверы и останавливает созданные им процессы по Ctrl+C. Python берётся из `.venv`, переменной `PYTHON` либо системного `PATH`. Требуются предварительные миграции и установленные зависимости, как описано ниже.

## Установка на другом компьютере

Node.js 22.12+ (или 20.19+), Python 3.12+. В корне репозитория:

```powershell
npm ci
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
# Необязательно: создать синтетические данные для демонстрации.
.\.venv\Scripts\python.exe manage.py seed_demo
npm start
```

На текущем ноутбуке Python установлен локально через uv; `.venv/` и `.tools/` исключены из Git. Они не нужны в репозитории и не должны передаваться вместе с исходным кодом.

Отдельный запуск:

```powershell
# Терминал 1
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
# Терминал 2
npm run dev
```

## Реализованные сценарии

- Главная с анимированной орбитальной графикой, прозрачными панелями и адаптивной композицией.
- Каталог опубликованных задач: поиск, отрасли, готовность, минимальный балл, сортировка и закладки.
- Карточка с полным брифом, детализацией рейтинга, копированием ссылки и выгрузкой Markdown.
- Мастер задачи: исходная идея → вопросы навигатора → контекст → обзор → ручное подтверждение публикации.
- Черновик формы автоматически сохраняется на устройстве; кнопка сохранения отправляет его в выбранное пространство.
- Создание и редактирование профиля команды, включая создание прямо из формы отклика.
- Отклик: команда, идея, план, сроки, необязательная ссылка на прототип.
- Общее рабочее пространство: опубликованные задачи, черновики, отклики и фильтры по команде/статусу/задаче.
- Принятие и отклонение откликов с подтверждением; разрешён выбор нескольких команд.
- Редактирование задачи с пересчётом рейтинга сервером.
- Явный деморежим, состояния загрузки, ошибок, пустых списков, недоступной сети и повторных запросов.
- Мобильная навигация, управление с клавиатуры, нативные модальные окна, `prefers-reduced-motion`.

## API и настройки

Типы контракта — `src/types.ts`, клиент — `src/api.ts`. Все URL заканчиваются `/`, как ожидает Django. По умолчанию запросы идут на `/api/v1` того же origin. Vite проксирует `/api` на `http://127.0.0.1:8000`, поэтому в разработке не требуется отдельная настройка CORS.

Необязательные настройки в `.env.local`:

```dotenv
# Адрес Django для dev/preview-прокси. Переменная доступна только Vite.
API_PROXY_TARGET=http://127.0.0.1:8000
# Необязательно: публичный абсолютный URL API, зашивается в сборку.
# VITE_API_BASE_URL=https://api.example.com/api/v1
```

`VITE_*` доступны браузеру. Не помещайте туда секреты или ключ AI. Существующий Django-провайдер AI работает на сервере; интерфейс различает базовые вопросы (`mock`) и внешний AI.

| Действие                     | Запрос                                                           |
| ---------------------------- | ---------------------------------------------------------------- |
| Загрузка общего пространства | `GET tasks/?include_drafts=true`, `GET teams/`, `GET proposals/` |
| Вопросы по исходной идее     | `POST tasks/analyze/` → `{draft_text, card}` (текущие ответы)     |
| Создать / изменить задачу    | `POST tasks/` / `PATCH tasks/{id}/`                              |
| Опубликовать                 | `POST tasks/{id}/publish/` → `{confirmed: true}`                 |
| Создать / изменить команду   | `POST teams/` / `PATCH teams/{id}/`                              |
| Откликнуться                 | `POST tasks/{id}/proposals/`                                     |
| Решение бизнеса              | `POST proposals/{id}/decision/` → `{decision: "accepted"}` или `{decision: "rejected"}` |

Серверные поля `id`, `score`, `readiness`, `status` и временные метки не отправляются при сохранении брифа. Для изменения опубликованной карточки пользователь отмечает подтверждение под рейтингом; клиент отправляет `confirmed: true`. Без него сервер возвращает 400 и сохраняет прежнюю версию. Балл после сохранения берётся из ответа сервера. Предварительный балл повторяет `challenges/scoring.py`, включая исключение коротких ответов и заглушек.

В текущем API нет пагинации. Клиент явно сообщает об изменении контракта, если появится неполная страница с `next`; при добавлении пагинации нужно обновить `list()` в API-клиенте.

## Общее пространство и демо

По умолчанию используется настоящий API. Если сервер недоступен, интерфейс показывает ошибку и кнопку повторения. Переключение на демо всегда явное: через кнопку ошибки или выбор режима в шапке. Неудачная отправка не превращается в локальный «успех».

Демо хранит синтетические задачи, команды и отклики в `localStorage` (`sauron:demo:v1`). Закладки и черновики форм используют отдельные ключи для `live` и `demo`. Выход из демо не переносит данные на сервер.

В текущем Django MVP стоит `AllowAny`; модели не содержат владельцев задач или команд. Поэтому UI честно показывает **общее пространство** без фиктивного входа и разграничения прав. До публичного запуска бэкенду нужно добавить аутентификацию, владельцев и серверные проверки прав на чтение черновиков, редактирование и решения по откликам. Скрытие кнопок на фронте не решает эту задачу.

## Сборка и развёртывание

```powershell
npm run build
npm run preview
```

`dist/` содержит статическую сборку. Для production выполните `python manage.py collectstatic` и настройте статический сервер на выдачу `staticfiles/` под `/static/`; главную и `/api/` обслуживает Django. При отдельном домене API задайте `VITE_API_BASE_URL` перед сборкой и разрешите домен фронта в `CORS_ALLOWED_ORIGINS` бэкенда. Vite proxy работает только в dev/preview. Открытое развёртывание требует авторизации и серверных прав доступа; текущий режим рассчитан на локальное демо.

Маршруты используют hash (`/#/projects/1`), поэтому отдельный SPA fallback не требуется. Шрифты Golos Text, Cormorant Garamond и IBM Plex Mono загружаются с Google Fonts; предусмотрены системные fallback. При отсутствии интернета интерфейс остаётся работоспособным с системными шрифтами.

## Проверки

```powershell
npm run build
npm test
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
# Браузерные сценарии с временной БД, без изменения рабочих данных. Нужен Edge.
$env:RUN_BROWSER_TESTS = "1"
$env:AI_PROVIDER = "mock"
python manage.py test challenges.test_frontend
```

Unit-проверки покрывают границы рейтинга, исключение серверных полей, безопасные ссылки, ошибки сети/валидации и формат публикации. Browser-проверки проходят полный путь через локальный Django, сохранение состояния после перезагрузки, мобильные экраны, поиск, закладки и явное переключение на демо при сетевой ошибке.

Playwright использует установленный Microsoft Edge в отдельном headless-профиле. Для другой ОС можно заменить `channel: 'msedge'` в `playwright.config.ts` и установить Chromium через `npx playwright install chromium`. Рекомендуемый запуск выше поднимает временную БД и Django test server, запускает все четыре сценария и удаляет тестовую БД средствами Django. Отдельный `npm run test:browser` оставлен для ручной работы с локальной демо-базой и требует `.venv` для очистки тестовых записей. Скриншоты и трассы находятся в `artifacts/`, которое исключено из Git.

```text

  main.tsx          маршрутизация, шапка, футер и обработка ошибок

  Teams.tsx         каталог команд и форма профиля
  Workspace.tsx     задачи, отклики и решения

  demo.ts           отдельное локальное демопространство
  domain.ts         поля, отрасли и расчёт предварительного рейтинга
  store.tsx         состояние данных, закладки и уведомления
  types.ts          типы API
  styles.css        дизайн, адаптивность и анимация
```
