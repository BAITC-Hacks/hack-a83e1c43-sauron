# Sauron — пространство реальных задач

Полный фронтенд на React + TypeScript и Django API. Сайт соединяет бизнес с командами: от исходной идеи и уточняющих вопросов до публикации задачи и выбора отклика.

**Фронтенд:** [запуск, сценарии и инструкция для передачи](docs/FRONTEND.md). На настроенном компьютере запустите `start-sauron.cmd` или `npm start`; сайт откроется по адресу http://127.0.0.1:5173.

Ниже — документация существующего бэкенда из ветки `main`.

## HackAlem AI — API практических бизнес-задач

Backend MVP для кейса AI Sana. Бизнес описывает задачу обычным языком, получает уточняющие вопросы, дополняет карточку и видит её готовность к работе со студентами. После публикации команды смотрят общий каталог и отправляют свои предложения, а бизнес сам принимает или отклоняет отклики.

## Что можно показать на демо

1. Ввести короткий черновик задачи.
2. Получить от AI не меньше трёх уточняющих вопросов.
3. Дополнить карточку и увидеть, как рейтинг вырос.
4. Опубликовать задачу в общем каталоге.
5. Создать профиль команды и отправить отклик.
6. Принять один, несколько или ни одного отклика вручную.

AI не назначает команды автоматически и не добавляет факты, которых не было в исходном описании.

## Стек

- Python 3.11+;
- Django и Django REST Framework;
- SQLite для быстрого запуска или PostgreSQL через Docker;
- mock-провайдер AI по умолчанию, OpenAI подключается через переменные окружения.

## Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Проверка сервиса: `GET http://127.0.0.1:8000/api/v1/health/`.

## Данные для демонстрации

Команда создаёт 5 синтетических задач, 5 профилей команд и 5 откликов. Повторный запуск не создаёт дубли:

```powershell
python manage.py seed_demo
```

После запуска:

- каталог задач: `GET http://127.0.0.1:8000/api/v1/tasks/`;
- список команд: `GET http://127.0.0.1:8000/api/v1/teams/`;
- список откликов: `GET http://127.0.0.1:8000/api/v1/proposals/`.

## API-сценарий

- `POST /api/v1/tasks/analyze/` — вопросы AI по черновику;
- `POST /api/v1/tasks/` — сохранить карточку задачи;
- `PATCH /api/v1/tasks/{id}/` — отредактировать карточку и пересчитать рейтинг;
- `POST /api/v1/tasks/{id}/publish/` с `{"confirmed": true}` — ручное подтверждение и публикация;
- `GET /api/v1/tasks/` — каталог опубликованных задач;
- `POST /api/v1/tasks/{id}/proposals/` — отклик команды;
- `POST /api/v1/proposals/{id}/decision/` с `accepted` или `rejected` — ручное решение бизнеса;
- `GET/POST /api/v1/teams/` — профили студенческих команд.

Низкий рейтинг не скрывает задачу и не запрещает отклик. Каталог сортируется по рейтингу и поддерживает фильтры `industry`, `readiness_level`, `min_score` и `max_score`.

## Как считается рейтинг

Рейтинг показывает готовность конкретной задачи, а не известность компании. Максимум — 100 баллов:

| Блок | Баллы |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |

Для каждого блока API возвращает начисленные баллы, максимум и недостающие поля. Рейтинг пересчитывается после редактирования карточки.

Уровни готовности:

- 0–39 — черновик;
- 40–69 — рабочая;
- 70–89 — готовая;
- 90–100 — приоритетная.

## AI

По умолчанию работает детерминированный `mock`, поэтому для демо не нужен внешний ключ. Он возвращает структурированный JSON с вопросами и недостающими полями. Для OpenAI:

```powershell
$env:AI_PROVIDER = "openai"
$env:OPENAI_API_KEY = "your-key"
$env:OPENAI_MODEL = "gpt-4o-mini"
```

Ответ внешнего AI проверяется; при ошибке система безопасно возвращается к mock-режиму. Перед публикацией карточку подтверждает человек.

## Тесты

```powershell
python manage.py check
python manage.py test
```

Тесты покрывают AI-вопросы, пересчёт рейтинга, публикацию, каталог, отклики, выбор нескольких команд, отказ от отклика и idempotent seed-данные.
